# Risk register

Ordered by expected damage. Each risk has a trigger that makes it real, and a
declared fallback - decided now, so it is not improvised in March.

| | Risk | Trigger | Mitigation | Fallback |
|---|---|---|---|---|
| **R1** | **No viable route into Cameo.** Five candidates, none proven. | G1 (6 Nov) passes with nothing demonstrated. | Spike all five in S0-S1, cheapest first. Half a day each for (a) and (b). | Cameo drops to a documented manual import; programme delivers Polarion -> validated SysML v2. See [cameo-publish.md](cameo-publish.md). |
| **R2** | **Capacity.** 23.7 engineer-weeks for a pipeline from zero plus two integrations plus quality. | Any gate slips by more than one week. | The scope ladder in [ROADMAP.md](ROADMAP.md), applied from the top. | Drop in the published order. If all four go, move the deadline - in November, not March. |
| **R3** | **Requirement quality.** Vague requirements produce vague models, and no amount of prompting fixes "shall be easy to maintain". | The golden set in S4 shows a large not-modelable share. | Plan for a not-modelable output with a reason from day one; never force a result. | Report coverage honestly. A programme that correctly declines 40% of requirements is still useful; one that invents constraints is not. |
| **R4** | **Entity resolution.** 200 requirements say "the pump", "pump unit", "P-101". Extracted in isolation that is four part defs. | Part-def count grows roughly with requirement count. | Ground the registry in Polarion component work items or the product breakdown (S8). Two-pass extraction per [EXTRACT_PLAN.md](../EXTRACT_PLAN.md). | Registry stays hand-written. Works at pilot scale; does not scale to a real project. |
| **R5** | **The IR schema is wrong.** It is the contract between extraction and rendering; changing it late invalidates the golden set and the renderer at once. | G2 (20 Nov) fails, or the golden set keeps needing schema changes. | Agree it with an MBSE engineer in S1, before any prompt exists. Keep V2 scope explicitly out, per [VERSION_MANAGEMENT.md](../VERSION_MANAGEMENT.md). | Freeze the schema at G2 and record wanted changes as a V2 list rather than editing it mid-programme. |
| **R6** | **Data confidentiality.** Requirements often cannot go to a cloud API - and that applies to observability vendors too, not just the model provider. | Marked resolved for the model provider. Re-opens if the project changes classification, or if anyone proposes cloud tracing. | Provider decision recorded in `decisions/`. Experiment tracking is file-backed MLflow with no cloud component, so it does not re-open the question - see [decisions/0003](decisions/0003-experiment-tracking.md). | A local model, with the extraction-quality hit measured on the dataset rather than guessed. |
| **R7** | **Single point of failure.** One developer, no second reader. | Any absence longer than a week. | Write decisions down as ADRs as you go; keep CI green so the state is legible; no undocumented local setup. | The programme pauses. Accepted consequence of the staffing assumption. |
| **R10** | **Unattributable results.** Scores that cannot be tied to a model, prompt and dataset version make every quality decision from W13 onwards guesswork. | Any run whose score cannot be reproduced. | File-backed MLflow in W10-11, before the first numbers exist. Pin the version. | None worth having. This is why it sits in the holiday fortnight rather than competing with a gate. |
| **R11** | **Unstable element identity.** Model update (W20) diffs two runs; if entity resolution or naming wobbles, every diff reads as delete-plus-create and the feature is worthless. | Two runs on unchanged input produce a non-empty diff. | Identity anchored on the Polarion id, which the IR already carries. Grounding (W18-19) keeps its full two weeks precisely so naming is stable first. Checked at G6. | Regenerate every run, no diff report. The programme then delivers generation but not adaptation - half of what the role asks for. |
| **R8** | **Toolchain drift.** `opensysml` and its `sysml-grpc` service are young, and the API JSON mapping is marked experimental. | A version bump changes diagnostics or breaks the export. | Pin the version. Keep the hand-built-IR validation test as the canary - it fails loudly if behaviour changes. | Stay on the pinned version for the programme; upgrade deliberately after March. |
| **R9** | **Holidays.** Christmas is two calendar weeks at roughly half a week of capacity; Easter 2027 costs Karfreitag (26 Mar, in W23) and Ostermontag (29 Mar, in W24). | - | Already in the plan and in the capacity table. W10-11 carries no gate. | - |
